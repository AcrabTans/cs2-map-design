# 游戏现状与手绘规划（开发版）

左侧“数据来源”独立控制 Carto 游戏现状与手绘规划。游戏现状默认锁定；取消“锁定游戏现状”才可直接修改，但下次导入会覆盖这些修改。已有完整工程按来源信息自动识别，无需转换文件。

建议流程：

1. 导入当前游戏的 Carto 文件夹，显示游戏现状。
2. 在对应图层手绘设计；若以现状对象为基础，在右侧点“复制为手绘规划”，再修改副本。
3. 从文件菜单导出 PNG，放进 Image Overlay 的图片目录，在游戏中对照建设。
4. 建了一部分后，重新导出同一地图的 Carto 文件夹，再导入本工程。对应现状会更新，手绘规划保留。应保留一致的地图范围和坐标系；不同地图会拒绝合并。
5. 对已在游戏实施的规划，选中后勾选“已在游戏中实施”。默认隐藏，左侧可重新显示。不自动判断完成，也不自动删除规划。
6. 常规保存保留全部现状、规划及显示设置。源图层与规划仍使用相同的 Area、Network、Building 等功能分类。

“图层 → 单独导出手绘规划…”另存规划工程，包含规划几何、必要的父级／所属片区／立交范围副本和引用到的资产包，不含底图、地形和其他游戏现状。导出不切换当前完整工程的保存目标。含 LOD 时，会生成同名 .assets 文件夹，复制备份时需一并携带。

“图层 → 叠加导入手绘规划…”将规划加入当前完整工程，保留游戏现状与当前底图。重复导入时更新同编号规划，不重复叠加；只更新本文件包含的对象，不自动删除其他规划。资产包编号相同但内容不同时会停止导入，避免破坏已摆放建筑。缺少地理范围时会要求确认按相同坐标叠加；范围不同则拒绝。

推荐使用完整工程作为主要存档，单独规划文件作为补充备份。请勿用单独规划文件覆盖完整工程。显示开关只影响绘制和 PNG；完整工程以及 Carto 数据导出仍包含隐藏对象。
