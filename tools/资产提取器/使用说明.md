# 天际线Ⅱ本地资产提取器

双击 `启动提取器.cmd`，选择 `.cok`、资产包名称和输出目录，点击“开始提取”。这台电脑的依赖已配好，日常提取不联网，不调用任何 AI，没有模型 token 消耗。

默认输出到本文件夹的 `output`。窗口提供三个独立勾选项，至少勾选一项：

- 二维投影：`包编号.cs2assets`，保持原地图导入格式。
- 远景 LOD2：`包编号-lod2.glb`，整包一个文件。
- 中等 LOD1：`包编号-lod1.glb`，整包一个文件。

默认仅勾选二维投影；全选时一个资产包输出三个文件，单选时仅生成对应文件。未勾选的旧输出文件不会自动删除。只选LOD时不计算二维投影。

GLB包含真实的主模型几何、法线、节点变换、建筑来源编号和属性，不包含贴图或独立道具。各建筑为独立scene，默认显示首个有模型的建筑，不把全包叠在一个场景。相同几何在包内共享。坐标为米制、Y向上，Z=-游戏Z。

按主模型的精确名称查找对应LOD；缺少时标记missing，并记录缺失主模型，不用其他级别或不完整建筑冒充。窗口显示每级可用/缺失数量；详细记录在工作缓存的 lod1-report.json、lod2-report.json，GLB自身也包含记录。

当前地图仍导入二维 .cs2assets；GLB为后续三维显示准备，也可由支持多场景glTF的软件读取。地图三维显示本次未改动。图片及核验报告只留在工作缓存，不混入output。


保留主建筑名称、来源编号、分类、地块尺寸、二维投影、高度、面积，以及明确的人数上限。没有明确人数则为空，不从住户数换算；不导出资源经营数据，不保存完整贴图/三维网格。道具和升级模块不独立列成建筑。

## 已验证

- 原来的中式低层住宅：完整本地提取通过。
- OldTown：168 栋建筑；使用只读 Unity 建筑定义对接模型。
- 旧版 JSON Prefab 格式：工具可直接读取包内定义。
- China Pack：386 个主建筑，已生成投影并通过地图导入和摆放校验。
- 每次提取前后校验源文件 SHA-256，一致才报告成功。

## 二进制格式与大资产包

已增加 Odin 二进制 Prefab 读取，和原有文本格式自动识别。只读字段，不加载或执行游戏类型。资源包按目录及条目分段读取，不再限制为 1GB 以内，也不整包加载贴图到内存。已支持 ZIP64 大包及超过 4GB 的条目位置，分卷 ZIP 暂不支持，单条目解压上限为 256MB。

China Pack 的 1166 个二进制定义已成功读取；389 个 BuildingPrefab 中排除 3 个 ServiceUpgrade 升级附属模块。道路、道具、分区规则等不会独立导出为建筑。投影逐个生成，大包可能需要数分钟；窗口每完成 10 个建筑显示一次进度。

FreeUpdate02 的二进制定义现在可读取，但其中大部分公园/游乐场没有独立主模型，由地表及子物件组成。目前不拼合道具形成公园投影，遇到这种组合资产会报告未解析项并停止导出，不会生成缺项的完整包。

缓存现在保存每个已完成建筑的投影检查点；失败后重试会复用定义及模型校验码一致的结果。为适配地图单建筑最多 512 个轮廓，超额时仅允许去除总面积极小的轮廓，面积变化上界记入投影核验报告；超过容差仍报错，不粗略替换整栋建筑。

模型登记数量或边界与文件实际数据不同时，在模型完整性、索引和文件校验码通过的前提下使用实际模型，差异记入 model-warnings.json 及投影核验报告。

后续同格式的资产包可直接选择文件提取，无需再次交给 AI 分析。若失败，保留 `工作缓存/包编号/结果.json` 和日志即可定位。

## 本地环境与缓存

工具需要这台电脑现有的 Python 3.13、Node.js，以及 NumPy/Shapely/Pillow。UnityPy、TypeTreeGenerator 和模型解码依赖在工具的 `依赖` 目录中，不依赖 `.scratch` 里的临时脚本。搬到别的电脑需要重新配置运行环境；入口中的 Python 路径也要相应更新。

`工作缓存` 保存轻量定义、投影和日志，不保存整包贴图或完整三维模型。完成后不需要缓存时可自行清理；`依赖` 和程序文件应保留。

命令行用法：

    python 提取.py "完整的资产包.cok路径" --output "输出目录" --name "资产包显示名称"

地图程序已迁移至 `1024/Map Design`；资产按项目独立保存，程序不再内置项目资产。当前项目已有六个资产包。

选项命令行示例：

    python 提取.py "资源包.cok" --formats projection lod2 lod1
    python 提取.py "资源包.cok" --formats lod2


## UnityGUID 本体模型引用（2026-11-03）

部分地区资产会引用游戏本体模型。提取器现可通过只读 PrefabsMap 索引解析，自动寻找 Steam 游戏目录，或使用 CS2_GAME_DIR 指定安装目录。独立占地且具有主模型的 ServiceUpgrade 扩展会纳入二维导出并保留主楼来源编号。无主模型的地表扩展另作排除记录，不能误报为已导出。游戏及资产包原文件不写入。


## 安装目录中的 DLC（2026-11-03）

选择 Content/某DLC/Blob.cok，提取器自动配对同目录 Prefabs.cok；也可以选择 Prefabs.cok，自动切换至 Blob.cok 读取模型。若无单独 Prefabs.cok，沿用游戏 resources.assets 公共定义读取。请保持安装目录结构。包名称、文件名和缓存使用 DLC 目录名，避免多个 Blob.cok 互相覆盖。本机批量导出位于 output/DLC，各 DLC 独立子目录，二维和 LOD2 分文件；未生成 LOD1。
